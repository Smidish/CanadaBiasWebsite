# Same Campaign, Different Story

An interactive, scroll-driven presentation of a media-bias study of the **Quebec general
election** and the **Alberta referendum**, built as seven choose-your-own-path routes plus a
guided default path.

> ⚠️ **Every number, name and quotation on this site is simulated placeholder data.**
> It is generated by a seeded PRNG so the interface could be designed and tested before the
> analysis was finished. The measurement definitions, coding schemes and stated limits are
> real. See `methods.html` and §6–7 of [CONCEPT.md](CONCEPT.md).

---

## Run it

No build step, no package manager, no network needed — D3 is vendored.

```bash
python3 -m http.server 8777     # then open http://localhost:8777
```

It also opens straight from the filesystem (`open index.html`): everything is classic
`<script>` tags, so there is no ES-module CORS problem over `file://`. The only network
request is the Google Fonts stylesheet, which degrades to system serif/sans stacks offline.

## Deploying to GitHub Pages

**The repository root must contain an empty `.nojekyll` file.** It is in this repo — do not
delete it.

GitHub Pages runs Jekyll over your files by default, and Jekyll silently drops everything
whose name begins with an underscore. That removes `js/content/_entities.js`, `_data.js` and
`_manifest.js` from the published site (`_data` is a reserved Jekyll directory name as well),
so every page still loads and renders its static text while every global those files define
is missing — no rail, no doors, no figures, no interaction, and no error anyone would notice.
`.nojekyll` turns Jekyll off and publishes the tree verbatim.

If it ever happens again, the site now says so: a missing module puts a banner at the top of
the page naming the files and the fix (`assertDeps()` in `js/app.js`). Check the browser
console too — a 404 on a `js/content/_*.js` file is the signature.

Everything else is already deploy-safe: all links are relative, so the site works from a
project subpath (`user.github.io/repo/`) as well as from a domain root, and D3 is vendored so
there is no CDN to block.

```

js/scrolly.js         the step engine (scroll position → active step index)
js/stage.js           scene transitions + the ambient intro canvases
js/render.js          content object → page (scenes, figures, controls, tour)
js/app.js             rail, theme, progress, visited-path memory, contents rail, hero field
js/content/_entities.js   the cast: outlets, parties, groups, coding schemes
js/content/_data.js       every simulated dataset, one function per figure

js/content/rq1…rq7.js     copy + figure specs for each path
js/content/tour.js        the default path
```

## Adding real results

1. Replace the entity names in `js/content/_entities.js`. Everything downstream — labels,
   legends, tooltips, tables, the methods page — reads from there.
2. Replace the generator functions in `js/content/_data.js`. Each one documents the exact
   shape it must return in the comment above it; nothing else has to change.
3. Delete the simulated-data badge: it is emitted in `js/render.js` (`SIM`) and in the rail
   in `js/app.js`. **Leave it in place until step 2 is genuinely finished.**

Numbers quoted in the prose are computed from the same generators the figures use (see the
top of each `rqN.js`), so the copy cannot drift away from the charts when the data changes.

## How a route behaves

A route is a **scene**, not a stretch of page. Its stage pins to the viewport and scroll
position drives three sequential fades, handled in `js/stage.js`:

1. **Title card.** The route's name, opening and hero number fade in over a wash of the
   route's accent colour, with an ambient canvas behind them previewing the *shape* of the
   figure that is coming — ribbons for a stream, a lattice for a heatmap, a point cloud for
   a scatter, bars for a ranking (`PAINT` / `FOR_TYPE` in `stage.js`). None of the fades
   begins before the stage is pinned, so a title is never seen travelling up the screen —
   it appears where it will sit.
2. **Handover.** The title clears completely, then the figure appears in place — opacity
   and a hair of scale, never a slide in from below.
3. **Exit.** At the end of the route the whole stage fades to zero while still pinned, so
   the scene is gone before the next one's title arrives.

The only thing that physically scrolls is the column of step boxes riding over the stage.
The explorer and the takeaway sit in a `.route-tail` below the scene and fade in and out as
they enter and leave, so nothing from the previous route is on screen when the next title
appears.

Figures taller than the stage are scaled down to fit (`fit()` in `stage.js`) rather than
clipped or given their own scrollbar — a pinned stage cannot scroll.

Timings live in one place: `tIn` / `tOut` / `fIn` / `out` in `stage.js`'s `layout()`, and
the `.phase-intro` / `.phase-outro` spacer heights in `css/base.css`.

## The contents rail

`SITE.buildToc()` (in `js/app.js`) draws the left-hand list of what is on the page: the page
title, then one entry per route. It marks the section you are in, fills a pip per step as
you move through the active route, and jumps on click. It appears at ≥1200px, where `body`
gains a matching left padding; below that it is hidden and the top rail's path pips carry
navigation.

## House rules the figures follow

Enforced in `js/charts.js`, not left to taste:

- **One y-axis per plot.** Two measures become two stacked panels sharing a time axis
  (see Route 5A) — never two scales on one plot.
- **Colour follows the entity**, via a fixed palette slot. Filtering never repaints the
  survivors.
- Categorical hues in fixed order, capped at 8. Forms where every pair is adjacent
  (scatter, network) cap at 3 and otherwise use emphasis.
- Sequential = one hue light→dark. Diverging = blue↔red with a neutral grey midpoint.
- Every figure has a hover layer **and** a `Table` toggle, so no value is reachable only by
  hovering or only by colour.
- Palette validated against this site's own surfaces (`#faf9f5` light, `#191917` dark) —
  all checks pass in both modes.
- Light and dark are separately chosen palettes, not an inversion. The theme follows the
  system setting and can be overridden in the rail.
- `prefers-reduced-motion` disables step transitions; figures render in their final state.

## Browser support

Modern evergreen browsers. Uses `color-mix()` (with a plain-colour fallback),
`ResizeObserver`, and CSS `position: sticky`.
